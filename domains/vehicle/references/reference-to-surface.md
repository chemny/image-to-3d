# 建模参考到连续曲面的标准路径

适用于图片输入的新车模，以及需要放弃不可靠主体重新建模的任务。目标是一次集中完成合格首版，内部允许拟合、校准和返工；不承诺一次计算产生完美模型。车型坐标、截面、阈值和参考图留在任务目录。

## 1. 建模参考包

新任务默认九张整车图和六组结构特写。已有批准包可按实际覆盖复用；减少范围需记录用户指令及影响，不因缺资产静默删除视角。建模参考数量不改变锁定配置器的八个交互机位。

| ID | 整车图 | 必须提供的约束 |
|---|---|---|
| front / rear | 正前 / 正后 | 宽高、灯组定位、前后脸轮廓、边角转折 |
| left / right | 左 / 右侧 | 轮轴、前后悬、屋顶线、窗线、门缝和轮拱 |
| front-left / front-right | 两个前斜视 | 机盖冠部、前翼子板、前脸向侧面的复合曲面 |
| rear-left / rear-right | 两个后斜视 | 后车肩、后翼子板、侧面向尾部的连接 |
| top | 正俯视 | 车宽沿长度的变化、机盖、车顶和座舱收窄 |

斜视通常约45°，相机仍需标定，不能因标签而当成精确机位。正视图尽量接近正视；生成图不自动具有正交投影。

| ID | 结构特写 | 取景范围 |
|---|---|---|
| hood-fender | 机盖与前翼子板 | 中央冠部、两侧隆起、翼子板及风挡下沿 |
| fascia-lamp | 前脸与灯腔转角 | 灯腔、周边面板、前包围及侧面转折 |
| roof-cabin | 车顶与座舱连接 | 屋顶冠部、风挡/A柱、侧窗上沿及邻接面 |
| side-panels | 门板与车肩 | 窗下沿、肩线、两扇门、门缝及下裙 |
| rear-shoulder | 后车肩与尾部 | 后轮拱、车肩、尾灯、尾门边界及包围 |
| wheel-arch | 轮毂与轮拱 | 完整轮毂/轮胎、轮拱边缘及邻接车身 |

车型特征不同可替换名称，但应保留对应的体积、边界和连接覆盖。特写不能只给孤立部件。开门/储物区内部需要额外依据；闭合图不证明内部和铰链结构。

先交一张九视角总览和一张结构总览，按 [造型确认关卡](reference-approval.md) 取得版本明确的批准，再生成必要的独立图。原图优先复用。总览用于确认设计，不能按整张像素数声称每格高清。独立图默认目标原生长边≥2048；报告真实尺寸。低于目标时登记可用范围和限制，细小特征不足则补图，不用插值冒充信息。

配置、光照、轮毂和部件身份跨图一致；明暗应可读出体积。生成/推断来源分别登记。图间冲突先解决，不强迫一个网格追随矛盾结构。新增生成图不增加实车测量证据。

## 2. 七个阶段和退出条件

| 阶段 | 必须留下的产物 | 下一阶段条件 |
|---|---|---|
| 来源与范围 | 源图哈希、批准目标、旧失败史、功能范围 | 目标身份明确 |
| 参考定版 | 总览、逐图覆盖/来源/尺寸/限制、用户确认记录 | 当前版本已确认，建模所需独立图可用 |
| 相机与观测 | 机位、轮轴及独立校验点、逐图标注的轮廓/特征线 | 相机误差与造型误差已区分 |
| 曲面骨架 | 分区控制曲线/截面、依据和未知项、共享边界与连接类型 | 每个主体区域有支持它的图像观测与构建数据 |
| 主体施工与验收 | 主体灰模、曲面/曲率诊断、同机位彩色/叠图/关键点报告 | 整体体积、曲面和主要特征通过，证据绑定当前资产 |
| 细节与交互 | 从主体派生的分件、灯腔、轮系及实际开合/点选 | 主体回归通过，功能/接缝分别通过 |
| 首版交付 | 当前模型、锁定页面、GLB重载及各项实测 | 本路径检查与 first_version_gate authorize-delivery 均通过 |

主体未通过时停止扩大依赖它的细节施工，内部继续校准、重建或切换方法。已有可靠独立部件可保留，不能保留错误主体作为造型真值。保留最佳检查点、失败史和连续预算；改名不能清零同目标失败。参考确认是用户的设计决策，普通校准失败不是用户逐轮指挥节点。

相机与推断骨架需要联合校准时，允许生成明确标记的低详情诊断曲面候选用于实渲和锚点检查；它不代表 construction 通过，不计作首版，不授权细节扩建。诊断记录同时列出缺少的机位证据和主体缺陷。

实际施工的数据字段、曲面到 BufferGeometry、法线和活动件就绪检查见 [程序化车模施工规范](procedural-vehicle-build.md)。两份规范共用本文件七阶段与现有门禁，不另建独立状态系统。

## 3. 曲面骨架怎么建立

1. 同配置多图标定机位和尺度；可信尺寸用于绝对尺度，否则只声明相对比例。独立点不能与拟合点重复，轮胎拟合不能单独认证整车机位。
2. 逐图标注屋顶线、窗上下沿、肩线、机盖边界/隆起、轮拱及前后脸转折。保存像素坐标、参考ID及图像身份，不只填写“已参考”。
   每条观测写明 `feature_id` 和 `control_targets`，构建文件列出实际存在的目标参数键。不同区域不能复用屋顶线冒充肩线或轮拱；合法共享同一物理边界时保留相同特征身份。键存在仍不证明拟合成立，须通过标注图和实渲图核验几何影响。
3. 在形状变化处设置截面和边界网络：前鼻、机盖/前轴、风挡根部、门板、后轴、后车肩及尾部等按当前车决定。横向冠部和纵向弧度同时约束。不能把稀疏猜测截面直接扩成细节整车，不能把同一截面沿全车挤出后只圆边角。
4. 可用样条、放样或受约束的曲面片；工具按实际能力选择。位置共边是G0，光顺过渡需切线一致；需要更连续的反射再约束曲率。真实设计折线显式保留，禁止为了圆润全车抹平。插值C1、法线变平滑或增加面数均不证明外形正确。
5. 玻璃/窗框/密封边共享轮廓，门/机盖/尾门由可信载体切分，饰件沿载体安装。活动件登记轴心、边缘厚度、随动件和未知内部。主体调整后按关系更新，避免独立补片漂移。

## 4. 三类证据同时验收

- **轮廓**：校准后同机位红色溢出/另一色缺失，保持参考和掩膜身份，禁止非刚性拉伸。
- **特征与结构**：独立关键点和主要特征线的位置/尺度/连接；轮廓重合不能代替此项。
- **曲面**：灰模和反射条带或等效诊断检查鼓起、转折、接面反光连续性，并对照斜视/特写。条带本身不是实车曲率测量；光照变化不能冒充几何改善。

阈值在任务中预先冻结并说明依据；未校准不能填通过。之前讨论的投影长边1%只能作为候选实验阈值，不能成为通用高精度保证。真实工程精度需要尺寸、CAD或扫描；本流程验收的是与批准图片的视觉一致性。

## 5. 可执行路径检查

任务保存 `modeling-path.json`，运行：

```sh
python3 scripts/modeling_path.py check --task TASK/modeling-path.json --stage review --out TASK/review-check.json
python3 scripts/modeling_path.py check --task TASK/modeling-path.json --stage references --out TASK/reference-check.json
python3 scripts/modeling_path.py check --task TASK/modeling-path.json --stage construction --out TASK/construction-check.json
python3 scripts/modeling_path.py check --task TASK/modeling-path.json --stage details --out TASK/body-check.json
```

`review`只检查待确认总览/来源身份，不授权建模；`references`检查当前版本确认和逐图可用性；`construction`再检查每图观测、主体区域与构建数据、机位证据；`details`再检查当前主体验收证据。退出码2阻止推进；通过只证明记录及文件身份满足契约，仍需代理核验内容。它不是图生三维模型、曲面拟合器或系统级沙箱，不能自动判断人工审查真伪。最终交付继续使用已有首版执行门禁，不因新工具通过而绕过。

任务格式见脚本的常量和测试中的最小可用记录：`sources`与`boards`为path/sha256，`approval.board_hashes`绑定当前总览；`assets`登记ID、类型、尺寸、可用性和引用；`constraints`登记region、source_ids、带feature_id/control_targets的归一化观测点，以及JSON构建文件的path/sha256/targets；`cameras`记录验证状态与独立证据；`body_review`绑定model/constraints_sha256、全部视角输出、反射诊断和结论。

## 6. 如何验证“一次集中首版”

记录首个主体候选结果、内部校准/重建次数、因造型问题发生的用户纠错次数、失败与停滞原因、最终逐视角结果。明确区分参考设计确认和模型纠错。当前案例通过不能推出跨车型一步到位；只有实际模型通过且用户无需指挥普通返工，才能报告该实验成功。缺确认时只报告已完成准备，不能提前声称首版成功。
