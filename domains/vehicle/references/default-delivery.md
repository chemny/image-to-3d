# 默认交付规范

适用于新建完整车辆三维配置器。用户只需提供车辆图片和用途；代理负责专业步骤。以下为用户明确要求的跨案例默认产品规格，不是特定车型的参数。用户已有布局或明确缩小范围时可覆盖，须在任务记录说明；不能因资产未做完而静默删减默认功能并称完整交付。

## 当前功能基准：极氪 9X 最终稿

用户指定 [极氪 9X 最终案例](../examples/zeekr-9x/README.md) 为当前车辆配置器页面最终稿。后续车型直接复用该最终页的页面结构、样式和组件，仅替换车型数据与资源；基准不仅是功能数量，还包括版式、间距、字体、按钮、轮毂图标卡片、横排场景选项、方案摘要及保存区。未经用户明确要求不得重设计或简化，不能退回旧 Automotive Studio 重构页的简化功能。新车型名称、图标所表达的实际轮毂样式及资产说明可以适配，组件外观保持一致。交付前以相同桌面和窄屏视口对照基准截图；模型形状、配色等内容差异与页面结构差异分开检查。参考本地案例 `final/index.html`、`app.js`、`interaction.js`；素材包缺失时按本节功能清单实施，不声称已查看案例或已经复现。

已核对的最终页功能：左侧实时模型与拖动/缩放；底部八个预设视角及平滑切换，左右门、前舱、尾门、车灯操作及模型点选；右侧六种车色、三套轮毂、自然棚拍/日落暖光/深色展厅三种场景及选配摘要；保存方案同时本地保存和下载JSON、恢复、导入及PNG下载；右上角参考图弹窗（独立视角、八视角及六组细节总览）与复位。

新车型默认沿用上述功能集合；车色默认六种，保留原始外观，具体配色适配车型。八个预设角度参考该页功能覆盖，但方位标签、机位按新车确认，建模九视角与交互机位无需逐项完全相同。不照搬极氪的车型标识、几何、配置ID、固定坐标、资产哈希或已知视觉缺陷。前舱按车型实际机构实现，不把发动机舱宣称前备箱。

本规范另要求的参考图放大、当前三维并排刷新、自动环绕等属于补充要求；极氪最终页源码未证明已具备的项目，不冒称是该页现成功能。功能基准冻结不等于极氪整车形似通过；保留案例原有验收边界。

## 图片到模型

1. 按 [参考到连续曲面标准路径](reference-to-surface.md) 登记源图、来源与哈希。默认九个整车角度：正前、正后、左侧、右侧、左前/右前/左后/右后斜视、俯视。页面标签用明确方位；不可见结构标为推断，先解决跨图矛盾。已有批准包按实际覆盖复用，不能改写历史批准。
2. 默认六组结构特写：机盖/前翼子板、前脸/灯腔转角、车顶/座舱连接、侧门板/车肩、后车肩/尾部、轮毂/轮拱。带上邻接面，服务曲面和安装关系；部件名按车型适配，缩减须记录明确范围和覆盖依据。
3. 先交一张九视角总览和一张结构总览，用户确认版本后再制作必要独立高清图。已有清晰原图优先复用。独立图默认目标原生长边至少2048像素；记录实际尺寸与可用范围，不以插值或总览整张尺寸冒充每格细节。图片数量和像素达标不等于跨视图一致。
4. 冻结批准参考、配置和部件依据，逐图提取观测、标定相机、建立分区曲线/截面和共享曲面。主体灰模、叠图、特征和反射诊断通过后再扩大依赖细节，最后接入锁定Three.js配置器；不能以静态图片换色代替。

## 两阶段质量

- 首版（手板）：从一开始逐视角对照批准图，主体比例、轮位、窗线、曲面及关键结构先过关，再补部件与授权交互。明显盒状、宽缝、浮件和粗坯不可称首版完成。
- 细化交付：冻结首版基线，在其上改善曲面、灯腔、接缝、轮毂、材质与开合结构；持续执行fidelity-loop.md的固定机位渲染、测量/叠图、看图、返工及回归。首版与最终交付分别验收，不靠用户逐轮指挥修补。
- 以尽可能贴近批准图片为视觉目标；不保证像素完全一致、工程尺寸准确或未知结构真实。没有接通并验证的自动修形能力不能宣称已实现。

## 页面默认分区

| 区域 | 默认内容与验收要求 |
|---|---|
| 左侧主区 | 实时三维模型；拖动旋转、缩放、闭合/展开均完整取景 |
| 模型下方 | 简短明确的视角按钮、平滑视角过渡；左右门、前机盖/前舱、尾门、灯光等适用操作；自动环绕与复位。开合及灯光同时支持点选模型对应部位，按钮和模型状态同步 |
| 右侧车漆 | 默认六种有区分度的颜色，保留原始外观入口；颜色名称和数值按任务配置，保护玻璃、橡胶、灯具与固定饰件不串色 |
| 右侧轮毂 | 默认三套可切换的真实三维轮毂，每套完整四轮；一套遵循批准参考，其余为明确标注的设计选配，不冒充官方配置；几何变化真实可见 |
| 右侧场景 | 默认自然光、日落暖光、深色展厅三种；同时改变实际灯光/反射环境及背景地面，不能只改标签或背景色。场景切换保留选配及部件状态；形似验收使用固定中性场景 |
| 右侧方案 | 当前车漆、轮毂、场景等摘要；导出/导入选配JSON、本地保存/恢复、下载当前模型PNG。验证实际下载与重载恢复 |
| 右侧条件选项 | 内饰等仅在有真实三维或合格全景资产时提供，不能伪造。额外选项按车型和用户需求配置，不强制制造不存在的前备箱或内饰 |
| 模型区右上角 | 常驻“参考图”入口，随时打开总览、独立视角和局部图；详见下节 |

缺少默认轮毂变体或活动件时，在授权范围内制作并验证；确有阻塞则明确未完成，不用空按钮交付。默认功能是制作要求，不证明现有模板已经实现。窄屏可改为上下布局，保持同样功能可达，避免遮挡车辆。

## 参考图随时查看

- 本地打包批准总览、独立视角及局部图，记录来源、版本、哈希与推断范围。右上角入口无需离开配置页即可打开弹窗/抽屉，可选视角、查看原分辨率和放大，关闭后回到当前模型状态。
- 切换参考视角时，可映射到有证据的模型预设机位，平滑切换并提供当前三维画面并排对照。局部图无对应机位时仅查看图片，不假装已对齐。
- “实时查看”必须展示当前模型版本与当前配置；若用截图对照，应在动画落定后重新捕获并注明是当前截图，不能复用旧模型截图。打开图库不悄悄重置车色、轮毂、场景和开合；关闭恢复查看前机位或明确保留用户选择。
- 验证入口位置、全部图片加载、切图/放大、关闭/Esc、焦点回退、手机可达性、模型操作后的对照刷新及状态保留。只显示按钮不算功能完成。

## 能力边界与任务验收

通用模板目前已有车漆、场景、轮毂绑定、方案保存和基础参考图库；底部全部动作、模型点选、参考放大及当前三维并排刷新等须逐项核实并按任务适配。交付记录区分“规则要求 / 模板支持 / 本案例实现 / 本案例实测”。按本规范建立任务验收表，缺项保留needs_revision或blocked；不把文档更新当作页面已更新。

颜色值、相机坐标、铰链参数、轮毂几何、车型名称与图片保存在案例，通用默认不写入memory。

## 锁定模板的实际执行入口

新建完整配置器使用 `assets/locked-configurator-v1/`（`zeekr9x-layout-v1`），禁止新写一套HTML/CSS或以基础assets/web模板替代本默认交付。旧资产整理工具仍可用于诊断，不能绕过该交付门槛。

```sh
python3 scripts/locked_configurator.py build --config CASE/vehicle.json --model CASE/model.js --out CASE/web-v1
python3 scripts/locked_configurator.py check --out CASE/web-v1
```

build只写新目录。车型名称、说明、六种车色、三套轮毂、三种场景、八个机位、参考图路径和部件绑定均由vehicle.json提供；不允许注入HTML。模型适配器只构建Three.js对象，禁止触碰DOM或加载额外脚本。适配器须实现buildVehicle()，返回root、paint、parts（group/axis/angle/value/target）、wheels、lights、setWheel(n)、animate(dt)；以当前源码接口为准，缺能力不得伪装通过。

index.html、style.css、app.js和vendor由规范目录哈希锁定。check同时核对规范目录和案例文件、配置数量与格式，并静态扫描模型适配器的页面操作。静态扫描不是安全沙箱，适配器仍须代码审查。模板变更必须取得用户明确批准，建立新模板版本及变更说明；禁止重新计算锁文件来绕过失败。

前后储物区默认按钮明确标为“前备箱”“后备箱”，与同一部件状态绑定，不用“前舱”“尾门”替代用户指定的功能名。当前任务已要求两者时须制作可见内部区并验证按钮、模型点选、反向关闭及保存恢复；不存在该机构的车型按实际证据与用户确认调整，不伪造实车能力。

交付必须额外执行真实浏览器检查：固定桌面1500×960与窄屏390×844，和极氪最终页对照stage/aside/轮毂卡片/场景区/操作区/参考入口的布局与计算样式，保存双方截图。车型内容允许变化，结构、间距、字体与组件排列不允许未经批准变化。模板静态检查不代替截图和实际功能验收。

自动版式回归使用 `scripts/validate_locked_layout.mjs`：

```sh
PLAYWRIGHT_MODULE=/existing/playwright/index.mjs node scripts/validate_locked_layout.mjs --url http://localhost:PORT/new-case/ --baseline http://localhost:PORT/approved-zeekr-final/ --out CASE/layout-review-new --chrome /existing/chrome
```

输出双方桌面/窄屏截图和布局差异JSON，失败返回非零。只使用已有浏览器依赖；不自动安装。脚本检查布局和样式，不能代替模型造型验收或证明所有像素一致。
