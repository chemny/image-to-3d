# 完整首版与内部连续验收

用于按图片制作可交互车辆首版。先确认用户需要的功能范围；普通用户只需提供图片和用途，代理负责专业步骤。目标是减少用户逐轮纠错，不承诺内部零迭代或任意输入一次高保真。

## 五个关卡

| 关卡 | 执行与完成条件 |
|---|---|
| 参考定版 | 按 reference-approval.md 先提供一张多角度总览和一张结构总览；默认九视角及六组结构特写，按 [参考到连续曲面标准路径](reference-to-surface.md) 检查覆盖和用途，用户范围覆盖须记录。取得版本明确的批准，区分来源与推断 |
| 结构规划 | 建模前列出静止载体、活动件、随动饰件、材质角色与可选变体。仅为授权范围内的开合功能规划分件、轴心、边缘厚度和内部可见区；不要求每辆车有前备箱或相同门数 |
| 主体造型 | 先保存逐图观测、分区曲线/截面和共享边界依据；比例、前后悬、轴位、轮径、屋顶/窗线、多视角轮廓先通过。灰模和反射诊断分别检查连续曲面和特征棱线；明显盒状时改变骨架/截面表达，不能全车磨圆或靠灯光隐藏。按 modeling_path.py 检查记录，主体失败暂停依赖它的细节施工 |
| 细节与交互 | 灯、格栅、饰件及轮系依参考安装；按 interaction-contract.md 验证范围内功能。按 seam-diagnostics.md 检查衔接。开启后无重复闭合壳体、漂浮饰件或明显穿插；未知内部结构注明推断 |
| 整体验收 | 固定目标逐视角对照、原材质与灰模、闭合与展开构图、移动布局、状态保存恢复和实际导出分别检查。视觉、结构、功能分开作结论，全部关键项通过才称完整首版 |

## 用户介入与停止

用户确认参考后，代理在已授权范围内连续完成制作、评审和返工，再提交完整首版；不让用户逐轮决定是否继续普通修补。目标冲突、需额外授权或实际阻塞才请求决策，不以本流程绕过用户另行指定的确认节点。

每轮按 fidelity-loop.md 执行固定机位渲染→测量/看图→修正→相关视角回归。与旧版本比较说明修改收益，与批准参考比较判断是否达标。预算耗尽保留最佳候选并明确未通过；不得靠改名重置预算。用户接受某案例首版，记录该案例验收范围，不推导成跨车型成熟度证明。

## 交付记录

保存目标版本、功能范围、部件归属、相机、变更原因、逐项结果、失败与修复证据。记录交付能力属于规则、通用模板支持、任务适配还是实际验证；规则已写入不等于模板已经实现，不等于无人值守修形已接通。

案例坐标、特征名、缝宽、动画参数、相机偏移、参考图、截图及大模型留在任务/案例；不要复制进通用默认值或 memory。来源不明的隐蔽结构不因生成或用户选中就变成工程事实。

## 首版最低质量与最终交付分级

后续相同类型案例的首次用户预览，至少达到已接受成熟首版的完整度：可辨认车型比例与特征、连续曲面与保留棱线、无显著浮线/宽缝/残留壳体；授权范围内的真实部件、顺畅动画、直接点击、状态同步及保存导出可用，桌面和窄屏构图可读。功能按当前车型范围选择，不强制复制某车全部选项。未经用户允许不得将明显粗坯作为首版完成。

首版基线需在案例目录冻结用户接受记录、文件哈希、源码和可运行页面；以后优化另存候选，可随时对照回退。首版通过不能覆盖最终交付：最终交付还须逐视角接近批准参考、关键结构/材质一致、展开及局部近景无明显缺陷，并完成当前资产功能回归。用户接受首版不等于认可隐藏结构为实车事实。

用户可在看过具体差距和功能结果后，明确决定以当前候选作为该案例的最终稿。此时保存用户决定、接受范围、资产哈希、已通过检查和未达标的逐视角问题；标记为“用户接受的案例最终稿”，保留视觉验收的 `needs_revision` 或 `not_verified`，不得改写为 `passed`，也不得宣称已获得高保真或跨车型验证。只有用户明确改变交付目标时才使用这一记录，不从沉默或一般进度确认推断接受。

已接受的案例说明见 [ZEEKR 首版基线](../examples/zeekr-first-edition/README.md)，案例功能数量不作为通用强制项。


实际执行须同时遵循 [首版执行门禁](execution-gate.md)，绑定当前运行资产和逐视角证据；不得仅凭手填结果或旧截图声称通过。
