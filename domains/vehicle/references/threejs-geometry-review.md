# Three.js 局部加工与验收

适用于已有可信底模、部件身份和有限改动域的加工。改动算法按任务生成；本规则不提供任意车型的自动修形器。与 [路线选择](tool-routing.md)、[特征保护](feature-protection.md) 和 [质量评审](quality.md) 一起执行。

## 1. 固定坐标域与基线

记录输入哈希、节点/primitive、顶点属性、节点矩阵、单位、参考相机与运行时依赖。分别标明几何 POSITION、物体/世界坐标、UV、材质语义坐标和 shader 生成坐标；它们可能不同。光照变化和换基线收益分别记录。

检查门缝、窗线或安装区时，使用其实际定义的坐标域。必要时以真实载体的三角形和重心坐标映射到语义属性；映射歧义、射线未命中或载体缺失时停止该项加工。不要把 POSITION 直接代入另一个坐标域的边界函数。

## 2. 先冻结保护，再修改

冻结允许位置/法线改动域、部件安装关系和非目标属性；域与阈值来自当前证据。零变形区跳过属性重写，避免浮点误差或法线再次归一化污染保护域。微小量截断须在任务中说明精度理由，不能通过放宽 lock 来让失败候选过关。首次失败保留，再修算法。

不盲目合并重复顶点；相同位置可能属于不同 UV、锐边或壳体。安装构件同时复核载体、密封件、玻璃边缘、旧安装区和两侧关系。独立节点 transform 能否满足这些关系由实际模型决定。

## 3. 同步形变、法线与着色器

连续变形 F 的法线使用相应局部 Jacobian 的逆转置运输，随后归一化；检查奇异变换、绕向及退化三角形。正 Jacobian 只说明局部定向，不证明没有自交、边界漂移或形似正确。

检查 shader 是否重建法线或从旧语义属性生成曲面表现。原生 NORMAL 更新可能被 shader 覆盖；在需要的坐标空间运输最终参与光照的法线，检查 clearcoat、切线/normal map 等相关通道。避免 GLB 已变形而 shader 再应用一次位移。普通标准材质与自定义 shader 分别重新加载检查。

灰模和原材质保持同机位、灯光、曝光与对照尺寸。造型结论依赖几何和视觉证据，不能靠增加高光掩盖缺陷。

## 4. 保存与重新解码

派生 GLB 另存，核对输入原件未变、实际输出哈希及完整依赖。原生属性追加保留旧缓冲区可能导致文件变大：记录前后大小。去除旧数据、压缩或重新导出属于后续独立加工，需重做属性、角色与视觉验收。

重新加载交付 GLB 和交付适配器，验证实际解码后的属性及网页表现；内存截图不证明文件已修复。自定义 shader 的效果不能仅凭 GLB 宣称已复现，需完整交付适配器、参数和资源身份。

## 5. 分层评审

至少检查目标视角、相邻视角及未参与调参的独立视角，并保留灰模和原材质对照。分别给出保护、安装/接缝、模型完整性、网页功能、局部改善和整车形似结论。报告采样覆盖：最近顶点距离不等于全部曲面间隙证明；窄屏浏览器不等于物理手机性能。

局部改善有限时保留最佳候选与 needs_revision，不扩大范围宣称整车通过。同一目标反馈预算随版本与工具路线继承；相机不匹配、参考不足或底模不准时先重新诊断。
