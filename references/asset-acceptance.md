# 资产验收与独立测试

工作组织采用 [系统制作流程](systematic-production.md)：结构与表面分支共用参考、版本和展示；已有基线的替换执行 [采用质量阀](adoption-review.md)，退步或不确定的候选不替换已接受版本。本文正式认证/技术检查与迭代预览分别使用，不把预览进度等同认证通过。

结构可计算检查、实际可操作性和视觉还原分别给结论。`asset_contract.validate(spec)` 的 passed 仅代表声明一致；scope 是 legacy 或 asset-contract-v1，professional_quality_verified 始终为 false。它不替代已有几何检查，也不认证原图真伪、纹理字节、碰撞或美术质量。

| 验收层 | 需要的证据 | 不可代替的结论 |
|---|---|---|
| 源数据 | 冻结参考/Spec/资源哈希、尺度来源、原图与推断区域、标注不确定性 | 写了 source_notes 不等于来源已核实 |
| 几何与语义 | 有效层级、部件 ID、拓扑报告、可用 UV/法线、装配分界与枢轴 | 三角形存在不等于造型准确 |
| 功能 | 实际选件、局部换材质、所有变体、拆解/恢复、动作全程与组合测试 | 目标存在不等于浏览器交互通过 |
| 外观 | 同相机、同画幅、同身份对照；轮廓、关键点/线、局部结构、高光和遮挡检查 | 单机位截图或轮廓分数不代表完整还原 |
| 交付 | Three 实际加载；GLB 解析/真实导入；纹理哈希及缺失资源失败；材质、层级、相机、动画/变体保留核对 | 导出命令成功不等于 Blender 或其他消费端验证 |

每层写明“通过/失败/未验证”、证据文件、实际范围和剩余缺陷。按用户用途预先设置必要部件、操作和视觉门槛；展示件可以不要求交互，拆解教学必须看到真实分件和恢复状态。不能靠事后减少必要部件、降低阈值或略去失败交付目标放行。

开发回归使用已知问题样本及源数据失败注入：不存在的父件/材质、嵌套变体、过期哈希、漏贴图、缺 UV、错误动作目标、共享材质污染、动作后无法恢复等。检查输出的可观察行为；仅检查实现文本或生成文案不能算行为测试。

独立能力验证使用用户提供或批准的未见新样本，至少覆盖新车辆及一种非车辆产品；汽车、自行车、摩托车、玩具的具体覆盖以实际样本报告，不能用同一个样例重命名冒充。冻结输入、质量门槛、工具环境和时间预算，让独立执行者只拿任务与原始输入，不提供预期答案或已知修复。已用于调优的样本转入开发集，再换新的留出样本。

对旧/新流程比较，遵循 [分层测试](validation-plan.md) 的同条件、重复运行与失败计入规则。记录首版可运行时间、首版质量、达到门槛时间、返工/人工介入、总时长/工具成本、失败及未完成项。小样本仅报告观察结果，不宣称普适速度或质量优势。

单元测试与合成 Spec 属于软件回归。独立重建和高还原结论以具体任务的冻结输入、实际结果和未通过项为准，不在通用规范中保存某一轮“尚未提供样本”的临时状态；不能将软件检查通过改写成能力已证实。

## 局部形体的独立复查

重要凹槽、分叉、收窄和层叠按 [局部形体施工](local-form-construction.md) 逐区绑定必需视觉检查。记录旧/新/原图、侧向深度、连接边界与保护项；作者自评、独立复查、数值指标分别保留。局部未通过不因整体轮廓或功能分高而放行。局部开发改进不自动证明完整模型通过，也不能改变既定总体门槛。


## 制作标准 v1 扩展

参见 [通用制作标准](production-standard.md)：新增生产契约、真实表面绑定、采样距离/镜像检查、捕获绑定的局部多视角记录以及显式修复审查。新项目在 Spec 阶段强制完整契约；旧项目保持兼容但不追认。规则完整性与视觉还原质量分别验收，未见对象效果需另做独立测试。


## 轻量展示交付

接入 [轻量展示交付 v1](lightweight-delivery.md)：新建构建默认采用独立或锁定模板兼容的无损压缩数据，界面不重复加载完整几何。分别记录展示资产预算、解压规模及设备性能；现有功能、视觉、交换验证和采用质量阀保持有效，打包通过不代替这些结论。
