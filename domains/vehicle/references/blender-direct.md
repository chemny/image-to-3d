# Blender 直接建模路线

## 选择与切换
- 用户明确选择 Blender 时采用本路线。用户只说不使用 Meshy/Tripo 时，先检查可复用资产与本地加工能力，不将排除服务等同指定 Blender。
- 已确认没有可用 API 额度/凭据且用户已授权制作：先按 [加工路线](tool-routing.md) 检查候选复用和所需能力；确需本地复杂建模时说明采用 Blender 后继续，保留 API 准备文件和任务记录。用户要求必须使用指定 API 时，先说明限制并等待其选择。
- 仅尚未选择服务时不要求选服务才能开始：已有 GLB 优先原生加工；无底模且需要复杂曲面时可说明采用可用的本地 Blender。服务生成仍按实际授权与预算执行。
- 不把超时或限流认定为余额不足；不删除不确定提交标记。切换路线不代表服务端旧任务已取消或退款。
- Blender 建模不消耗 Meshy/Tripo 额度，但 AI 图片生成、代理服务和云算力仍可能计费，不称整条流程完全免费。

## 建模流程
实际执行使用 [CLI 分阶段工具](blender-pipeline.md)，统一参数和阶段快照，按实际渲染证据评审。
先按 [集中优化流程](model-optimization.md) 选择基线并写任务卡。有可用同车模型时复用；以下基础构建仅用于缺少可用底模的任务。比例与轮廓是后续结构/细节的进入条件，不为凑齐整车而扩展未经验证的粗坯。
1. 查看原图及已有多视角参考；登记真实可见特征与推断区域。图像生成不可用时，用原图继续，保留背面和内饰等未知项，不能伪造已生成参考图。
2. 检查本地 Blender 可运行。以参考图建立相机、轴向与尺度；有真实尺寸则使用，无尺寸则记录估算。透视照片不直接当正交蓝图。
3. AI 编写并执行任务专用 Blender Python 脚本，必要时使用可用的 Blender 操作工具。脚本和输出保存在任务目录，不把特定车型几何写入 Skill。先建立轴距、轮距、车高、前后悬及车窗轮廓，再以截面/曲线构造连续车身曲面。
4. 基础比例/轮廓通过后，按当前范围制作车灯、格栅、轮拱、门板、玻璃和轮毂。按参考建立轮毂辐条数量与形状、轮胎厚度和轮轴位置；需要开门时才补车门厚度、内侧与铰链轴心。镜像、细分和倒角按部件使用，不能靠堆叠基本体或无限增加面数代替形状校准。
5. 保存版本化的 .blend 和可重运行脚本；输出 GLB 候选。通过 inspect_model.py 检查，渲染多角度灰模并以接近原图的相机对照比例、轮廓、灯组及轮毂，先修几何，再调材质灯光。
6. 每个检查点记录实际改进及差异。同一连续修复链的 `max_repair_rounds` 由任务卡按证据和预算设定；一次集中优化可以包含多个顺序阶段。连续两轮无实质改善时重新诊断基础资产/参考/方法并保留最佳版本，不能给同一失败目标改名续试；仍未达标写 needs_revision，不声明达到原图精度。
7. 通过候选检查后，回到统一集中优化：按实际问题选择原生 GLB 加工或继续 Blender，处理范围内的内饰、GLB 优化、网页绑定和交互验收。各路线使用相同质量标准，不因基础候选由 Blender 生成就固定后续工具。

## 产物与能力边界
在 project.json 中记录 modeling_route: blender_direct；候选记录 origin: blender_direct、文件路径、使用参考、估算尺寸、推断部位与 verdict。API 候选保留原有来源和任务 ID，不改写成 Blender 成功任务。

本路线由代理针对车型生成建模脚本，Skill 没有一键恢复任意车型精确几何的通用转换器。仅凭一张图，隐藏结构仍需推断；渲染改善材质与光照，不能自动修复错误几何。达到高保真取决于参考充分程度与实际建模校准，不能承诺自动与原车完全一致。
