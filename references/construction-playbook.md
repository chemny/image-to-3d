# 从图片到首版：执行操作

本文件是执行代理的工作指引。脚本能验证数据和生成指定曲面，图片语义和三维推断仍需代理完成。一次构建目标是比例、控制线、分件关系成立的主体，不保证单图一次生成完美隐藏面。

## 1. 先定义可判定的目标

读取原图并记录对象、用途、可见/遮挡区域。建立三层清单：主要体量、连续曲面/独立组件、局部识别特征。每项填 reference_id、像素 ROI、原图观察、推断、置信度、component_id、参数或材料绑定、验证视角。原图、批准生成图、结构猜测分别登记，不混作测量真值。

车辆采用已确认参考范围：九视角总览和六组结构特写；其他对象按 [参考集标准](reference-set-standard.md) 规划视角和特写，参考准备必经，已有充分资料需覆盖记录才能复用。生成图先确认造型，随后提取高清独立图；同一零件在多图中应语义一致。不得为了降低误差重生成参考图。参考确认是造型授权，不自动批准几何精度。

## 2. 把观察变成约束

网格用于定位与防漏检；结合 [锚点校准](anchor-calibration.md) 的实际几何投影和局部轮廓检查，不把网格本身视作三维约束。标注轮廓、可识别点、材料分界和真实分件线，保存原像素坐标、原图尺寸与不确定度，不先画候选模型再把候选投影当参考标注。区分视角相关轮廓极值和固定材料特征，二者不能强行作为同一3D点。

先冻结开发集和独立验收集。开发期间可以用诊断集定位错误，但使用过其误差来选择方法后，它就不再是最终盲测。真实尺寸未知时使用明确的相对尺度。坐标系、对称假设和可见性必须记入 Spec。

## 3. 相机与粗尺度先解耦

用足够分布的稳定特征拟合机位，先检查遮挡和标注语义。分别冻结形状调相机、冻结相机调形状，再比较误差向量与参数敏感性。部分参数不可辨识时固定有依据的自由度，不同时放开所有参数。纯单视角允许多个合理3D解，输出假设。

退出条件：重点视角的控制特征与比例可解释；残差在预先定义的目标和标注不确定度下可接受。不可通过事后放宽阈值或只看平均分出关。未通过时可做隔离实验，不在有问题的基准上添加生产细节。

## 4. 先定局部体积与曲线结构，再建主体

每个区域选择表达：旋转体用于轴对称部件；截面放样用于沿轴变化的外壳；Bezier 控制网用于连续面；硬边与开孔单独表达。不要把所有零件默认成圆角方块。对分叉、厚度、凹入和收窄，使用 [局部形体施工](local-form-construction.md) 记录真实几何关系与保护视角；软体可以用体积融合、分支网格或足以表达局部关系的参数化变形；若整体形变与表面画线不能形成所需体积，就应更换表达，不继续只改外轮廓。选择外部构建器时输出当前 core 支持的 mesh，并保留可重建来源。

明确轮廓曲线、肩线、边界曲线和截面。每条曲线记录参考来源、控制点、关联参数、邻接面。相邻面用同一组边界控制点；平滑区域校对跨边切向，真实折线保留。由低密度控制网生成曲面后再提高采样，不能用细分掩盖错误的控制网。

输出可重跑的 Three.js factory，部件命名与 Spec 一致。Bezier/放样控制点必须来自分析或明确推断；工具不会自动从照片恢复这些值。主体灰模先通过侧面、正面、斜视和俯视检查，再进入灯、缝线、内饰等细节。

## 5. 用误差决定修什么

固定相机/视口/模型版本抓取：参考、灰模、材质图、二值轮廓。红色表示模型多出来的区域，蓝色表示模型缺少的区域。除整体轮廓外，单独检查窗线、灯线、开口、轮拱和曲面高光。

每次记录：错误区域→可能原因→只改哪些参数/代码→预期影响→保护视角→前后证据。相机、几何、法线/拓扑、材质/灯光分开定位。连续两次无显著改善时检查表达能力、特征对应和约束可观测性，停止盲调同一批参数；不把普通技术返工交给用户决定。

## 6. 装配后再做表现

固定件和活动件有清晰归属。门板、玻璃、把手跟随同一动作节点，门缝来自实际边界，铰轴有安装关系。舱室用正常内衬/隔断封闭，不用挡住通道的大黑板补洞。连接点/采样动作检查与实际多视角查看并用；接点通过不等于所有表面无碰撞。

先中性灰检查轮廓、褶皱与法线，再校对漆面、橡胶、玻璃和发光面。亮灯必须检查实际透镜，换轮毂必须检查几何变化。显示模板、按钮、场景与产品布局使用用户已确认模板；模型迭代不擅自重排页面。

## 7. 交付必须能复现

新目录保存参考版本、施工 Spec、控制网、源码、资源、相机、动作状态、截图、评审和未验证项。基础软件测试、开发案例回归、独立样本效果、运行性能分别报告。阶段工具检查证据身份，不能代替实际视觉判断。


## 制作标准 v1 扩展

参见 [通用制作标准](production-standard.md)：新增生产契约、真实表面绑定、采样距离/镜像检查、捕获绑定的局部多视角记录以及显式修复审查。新项目在 Spec 阶段强制完整契约；旧项目保持兼容但不追认。规则完整性与视觉还原质量分别验收，未见对象效果需另做独立测试。

## 已有资产迭代

已有模型先走 [通用修复流程](repair-workflow.md)：冻结比例与机位、判断几何表达，再局部施工。长黑色后窗、侧窗和实体连接件等不同语义边界各自建约束，不能因为同色而合并为同一控制锚点。关键边界改变触发关联件检查；不把整体缩放当局部比例修复。
