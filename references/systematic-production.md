# 新建与修改共用的系统制作流程

适用于车辆、玩具、器皿、家具及一般物件的新建和修复。作为现有统一执行入口的工作组织方法，复用参考、形体、修复、资产和展示工具，不建立新的 state/schema、审批系统或固定全量测试套餐。

## 推进方式

已有已接受基线时，前后对照同时用于采用判断：按 [采用质量阀](adoption-review.md) 复查本轮改动及其依赖区域。退步不采用，不确定保留基线；相互依赖的混合改动按组恢复。隔离候选仍可迭代，不能以技术检查通过替代外观审查，也不能用总分提高抵消明显退步。普通返工自行完成，只有设计冲突、关键参考缺失或超出授权范围才询问。

用户指定的不可改内容不是美术评分：仅衣服换色等明确范围应继续遵守。模型不能加载、资源损坏、交互失效等实际功能错误正常排查。既有数值检查继续报告实际结果，不能修改参考、伪造通过或删掉失败证据。

本流程允许先完成可运行的迭代预览，再优化未解决外观。现有工具的正式 build/export/mark 认证仍按各自契约执行；未满足时使用已有 diagnostic 预览并标注范围，不为推进流程填假通过，也不把未认证预览称为正式验收包。下文阶段是施工顺序，不要求每阶段新增审批文件。

## 六阶段与现有工具对应

| 阶段 | 实际工作 | 输出与复用入口 |
|---|---|---|
| 1 目标和参考 | 区分新建/修改、用途、已有依据和推断；只补关键缺口，确定当前版本和可改范围 | 复用 reference_plan、analysis、共用参考准入；保存基线和原图 |
| 2 区域拆解 | 稳定组件 ID；区分主体、接口、细节和材料区域；列出相关依赖与不可改内容 | 复用 Spec、asset_contract、repair_contract；不复制同一真值到多份表 |
| 3 重点样件 | 仅对风险高或方法不确定的局部先做小样，区分造型错、材质错和灯光错 | 同一实际几何/材质的局部预览；简单可靠修改可直接施工 |
| 4 分层施工 | 主体关系与体积 → 曲线/截面/接口 → 几何细节 → 纹理/颜色/材质 → 展示光照 | 复用 scene_build、构造计划、修复或外部生成适配；保留可重建来源 |
| 5 对照和功能检查 | 固定机位做原图/基线/当前对照，分别写技术结果和外观观察，整理剩余问题 | capture/compare、相关 asset-check、实际页面操作；候选可迭代，替换基线前检查局部退步 |
| 6 展示交付 | 按用户要求接入案例，说明采用版本、预览/认证状态、未完成项和恢复路径 | 复用 presentation-delivery；正式包用 export；不把审查页当模型页 |

已有模型从相关阶段恢复；结构不改时无需重做全部形体流程。主体比例和曲面走向明显偏离时先调整主体，再精修，避免用材质或小补片掩盖结构问题。

## 结构分支

1. 先检查比例、主体关系、轮廓及深度，校准机位后再解释投影差异。机位近似的图只作诊断，不输出精确还原结论。
2. 用真实曲线、截面、厚度和附着关系驱动几何。影响外轮廓、遮挡、接触或可见厚度的特征优先用几何；微小织纹、色差和反射优先由表面表达。
3. 整体形状用中性材质、轮廓/深度等视图检查；连接质量另用掠射光/条纹查看。反射条纹不是几何真值，不能把原图高光直接描成曲面凹凸。
4. 平滑、分片和变形后复核边界、附件、开口与法线。保留设计硬边，不全局平滑消除特征；记录改善及变弱的特征供后续调整。

具体算法和约束复用 shape-foundation、form-construction、continuous-surfaces 与 repair-workflow。

## 表面分支：纹理、颜色与材质

1. **区域与证据**：按语义划分底色、图案、表面微结构和材质响应；说明来源是原图、测量、生成补图或推断。单图不能唯一反演粗糙度、金属度或隐藏面。
2. **几何/表面分工**：厚刘海、布边、接缝体积、口沿等可见形体由几何承担；纤维、织纹、微起伏按观察尺度使用纹理/法线，近景必要时再增加实际微几何。不要把大褶皱压进噪声贴图。
3. **UV与尺度**：检查贴图方向、接缝、重复周期和不同部件的纹理密度；以目标窗口与近景共同观察，避免镜像拼接菱形、规则重复、颗粒过大或过度凹凸。
4. **照片纹理去光照按需采用**：先区分真实色块/印花与照明。低频归一化仅适用于有依据的照明污染区域；用保留图案的对照小样检查。不能对所有照片无条件去低频，也不能宣称由此恢复完整 PBR 参数。
5. **颜色与响应分开调**：固定曝光、色彩空间和灯光先核对底色，再调整粗糙度、金属度、sheen、clearcoat 和法线强度；按真实材料选择参数。底色字段相同不代表最终观感相同，照片纹理也需检查平均反射与色偏。
6. **换色按语义作用**：默认保留原配色；明确可换区域与固定区域。独立材质实例避免共享污染；默认色能恢复，换色不重置模型尺寸或相机。
7. **展示复核**：固定条件判断材料变化，再检查用户实际场景、缩放与转动；材质调整和展示灯光分别记录。不要用加亮灯光掩盖材质错误，也不要将灯具平板暴露到模型浏览画面。

几何不变的材质施工不强行接入仅支持几何的 repair_session；使用已有材质/资源字段和实际浏览器证据，明确尚无专用材质反演器的边界。

## 精简对照记录

优先放入现有任务报告，不要求新增专用 JSON 格式。保留：

- 当前输入、源码/Spec、模型和资源版本；可改范围及用户指定固定内容。
- 目标局部的参考、基线、当前结果；同机位/画幅/姿态/曝光。参数不能锁定时说明差异，不伪称严格对照。
- 分开记录结构、表面、功能观察；允许有改善、有不足、有未验证，不汇总成虚假的全模型通过。
- 剩余问题、下一项施工及恢复来源。对照同时记录采用判断；退步或不确定时保留基线及候选证据。

参考/几何/材质/相机变化时仅重跑受影响检查；依赖不清时扩大核对范围。局部开发检查可稀疏捕获，交接时覆盖实际用途的主要视角和交互，不默认每轮全量检查。测量、作者脚本和捕获工具可重复执行，避免代理反复手写同一逻辑。

## 能力验证与边界

跨对象验证区分结构问题、柔软/织物表面和光滑/硬质表面；使用已有案例做开发对照，再按需要选择未参与调参的对象验证泛化。无需为每个普通制作任务重复独立能力评测。

技术测试证明工具行为，前后截图证明所观察范围；都不自动证明整体高还原。宣称新旧流程效率或质量优势时，继续按 validation-plan 的同条件独立试验记录失败、返工、时长和可获得成本；没有可比运行不报告提升比例或 token 节省比例。案例参数与临时失败留在任务中，不写为永久通用规则。

## 版本恢复与案例接入

已有案例恢复、分批施工交接及实际展示更新，统一按 [版本核实与成果继承](presentation-delivery.md#版本核实与成果继承) 执行。复用已有任务报告记录成果的继承、延期或替代；不把已接受样件等同已上线成果，也不把接入检查等同视觉认证。字段、工具和边界仅在该处维护。
