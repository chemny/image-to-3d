# 集中优化任务卡（复制到任务 repair-plan.md）

## 起点与复用
- 本轮目标/交付范围：
- 输入原件、模型哈希与已选择基线；选择理由和比较证据：
- 已有可复用参考/相机/曲线/部件/材料及其身份；已通过区域：
- 需要重查/新建的内容及原因；已失败方法及不重复的原因：
- 原输入→所选基线→优化结果的比较机位；换基线和实际加工各自贡献：
- 车型/配置、单位/轴向、真实尺寸或估算依据；未知和推断区域：

## 判断与保护
- 接受的参考、相机对齐状态、预留独立点/轮廓；证据精度：
- 本轮重点形似特征；各视角的检查目标与任务阈值/视觉标准：
- 目标范围（资产质量/指定区域/完整外观）；关键特征组、独立样本及冻结计划身份；不支持的范围：
- 校准与独立样本分离；参与反馈后如何标记污染并补独立证据：
- 保护对象/顶点域、局部几何/UV/材料；允许跟随变换、明确允许重建的部位：
- 允许修改区域及过渡带、位移/变换上限；原件及回退位置：

## 有顺序的动作

- 按 [加工路线](tool-routing.md) 选择工具及理由；进入建模工具的具体能力缺口（如适用）：
- 改动持久化位置（配置/运行时适配/派生 GLB）；重新加载与实际交付版本复核方式：
- 节点变换/拓扑/索引是否改变；保护检查适用条件、必要的对应映射与重新绑定：

| 优先级/区域 | 问题与原图/模型证据 | 方法 ID 与任务脚本 | 依赖/允许变化 | 验证及退出条件 |
|---|---|---|---|---|
| 填写最影响本轮目标的动作 | 写实际偏差 | 从方法目录选择，不复制旧车坐标 | 已通过步骤可跳过 | 写该动作需要看的视图、保护检查与成功条件 |

- 主体轮廓未通过时，哪些细节动作暂停；是否有仅为看清问题的诊断动作：
- 执行预算与同一修复链反馈上限（max_repair_rounds 按本任务填写正整数及依据）；无实质改善时的方法复诊条件：
- 代表区域、适用前提、支持域、尺度化参数；最小可辨改善、允许回归及达到目标即停止条件：

## 结果与下次接续（执行后填写）
- 实际输入/脚本/参数/输出哈希与版本；查看过的证据：
- geometry / materials / function / performance 各自 scope、verdict 与未验证项：
- 按 [验收门槛](optimization-gates.md) 的记录检查结果；独立目标逐项结果、关键失败与范围修订理由：
- 保留的最佳版本、已通过区域/有效方法、回退或拒绝的步骤：
- 剩余形状差异/未知结构及所需新增条件；下次只做的差量步骤：

空项不代表通过。按实际范围填写，不要求模型任务先有照片才能修资产，也不把缺失参考包装成“更贴近真车”的证据。该任务卡适用于各工具路线；不是执行器参数。选择 blender_pipeline.py 时另按其 JSON 契约提供参数。
