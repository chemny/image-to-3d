# 参考目标驱动的连续返工

用于用户要求贴近指定图片的建模/优化。一次用户授权覆盖同一目标内必要的校准、检查和局部返工；普通失败不另发一版让用户决定是否继续。功能通过或优于上一轮均不是停止条件。

## 固定什么

1. 冻结用户批准的最终目标图、批准记录、逐视角 ROI、车型配置及 SHA256。用户明确选择生成总览为成品基准时，以该批准版本作为设计目标；原始图片保留来源用途，不再悄悄替换最终目标。结论叫“符合批准参考”，不叫工程级实车复原。总览和细节冲突时先记录冲突位置及可兼容解，只有目标本身无法兼容才请用户裁决。
2. 每个目标视角建立独立相机、裁切、尺度和锚点；冻结后每轮复用。参考相机不一致不能强制使用一个投影。先校准，后计分；不能逐轮重新拟合机位掩盖几何变化。相机必须修订时重测旧最佳版及当前版。
3. 提取排除文字、背景、阴影的轮廓，并登记屋顶/窗线、轴位、轮径、悬长、前后脸、灯具、轮拱及折线。每个关键部位绑定参考 ROI 和对应渲染；不能只测外轮廓就通过整车。
4. 冻结每项限值、标注不确定性和理由。边界/锚点误差按参考车辆包围盒对角线归一化，IoU 单独记录。限值不能小于标注误差；先用原候选、明显错误候选和合理边界样本检查门槛能否区分，再标记 calibrated。固定通用百分比、CLIP/SSIM总分或代理自报“相似度95%”均不能作为唯一门槛。禁止为通过而调宽阈值。

## 执行闭环

校准参考 → 渲染所有目标视角（闭门、匹配轮毂/灯态） → 轮廓与特征测量 → 同机位叠图/差异图及灰模看图复核 → 决策 → 修正 → 重渲染。看图复核由执行代理承担，不默认转交用户；记录可观察差异及证据，不能仅填 passed。

| 决策 | 代理下一步 |
|---|---|
| calibrate | 补 ROI、掩码、相机、阈值或缺少的证据；不能把未测量填成0 |
| repair | 继续当前任务，按最差关键项定位相机/比例/曲面/特征/材质原因；生成受约束的修改并重测全套视角 |
| rollback | 恢复保留的最佳版本，再改变修复方法；回归保护检查和所有受影响视角 |
| change_method | 连续两轮无可辨改善后，改变控制截面、分区方法或基础候选；不得简单加面、磨圆或只换灯光 |
| passed | 所有关键项通过，保护及功能通过，最终视觉证据齐全，允许交付 |
| blocked | 冻结目标冲突、权限/服务缺失或总预算耗尽；保留最佳候选和具体阻塞，不称“完成”，不让用户逐轮指挥普通修补 |

用户在了解当前差距后明确选择停止修形并交付该案例时，停止当前目标的返工，把接受决定和资产身份写入案例交付记录；未通过的视觉检查仍保持原 verdict。案例可以成为用户接受的最终稿，但不能把 `repair`/`calibrate`/`blocked` 决策改写为 `passed`，也不能用于证明方法在其他车型上已成熟。

任务冻结总预算、最小可辨改善和保护项允许回归。无现成预算时代理按复杂度确定并写入任务；连续两轮无改善触发方法复诊不是交回用户。方法切换不重置总预算。保留完整失败记录及最佳版本，不能只报最后或平均分。图像阈值全过而灰模仍明显盒状、灯具/窗线错位时仍返工。

反复使用批准目标调参属于 **target_conformance**，允许用于该目标的闭环；不能将这些参考称为独立验证集。跨车型泛化、未见视角或实车准确性需另有独立证据，继续遵守 optimization-gates.md。

## 自动化边界与接入

- `silhouette_review.py` 负责已对齐二值/alpha轮廓的实际数值计算；`optimization_review.py` 负责记录、关键点与保护关卡。它们不识别未知车型、不修模型。
- `fidelity_loop.py` 是离线决策器：读取冻结任务和一次实际测量，检查身份、覆盖、阈值、证据、回归与预算，输出下一动作。**它不渲染、不提取语义、不自动编辑网格**。收到 repair/calibrate/change_method 后由代理执行相应动作并再次调用；不能把脚本退出当作优化完成。
- 真正无人值守执行还需要任务级 render → measure → repair 适配器；若适配器未接入，报告“闭环规则/决策器已具备，车型接入未完成”，不得宣称车模已自动匹配。无需要求用户编写这些适配器。
- 必须保存每轮候选模型、相机、配置、测量、差异图、修复原因和决策。测量绑定当前模型及冻结计划的哈希，禁止旧截图复用到新模型。

## 决策器契约

`python3 scripts/fidelity_loop.py --plan TASK/plan.json --record TASK/round.json --out TASK/decision.json`

路径相对 plan 所在目录。输出以新文件创建，不能覆盖历史。plan 必填：references=[{path,sha256}]，checks=[{id,kind,op,limit,uncertainty,reason,calibrated,max_regression}]，budget={max_rounds,stagnation_rounds,min_improvement}。kind 覆盖 silhouette、landmark、visual、protection、functional；每个视角/特征用不同 id。op 为 min 或 max；visual/protection/functional 使用 min、limit=1、uncertainty=0 的二值关卡。references 至少含已批准参考；相机、配置、ROI和阈值校准证据也作为 references 冻结。

record 必填 plan_sha256、round（从1计数）、alignment（validated或unregistered）、model={path,sha256}、checks={id:{value,evidence:[{path,sha256}]}}。缺少值/证据返回 calibrate，非有限值或哈希错返回 blocked。value 必须来自实际计算或附图视觉评审，哈希不能证明评审本身真实。previous_best 可引用同计划已完整测量的一轮 JSON 的 path/sha256；用于检测超允许回退。history 是从1起连续完整的前轮记录数组，同样用 path/sha256 引用，用归一化最大超标量检查停滞。没有完整 history 不能伪报当前轮号或重置预算。

脚本测试只证明决策逻辑，不能证明图片自动拟合成功。真实车型完成全部接入并保留实际返工前后证据后，才可称该案例闭环运行通过。

## 执行适配器的最低证据

- 不能只创建决策 JSON：必须实际接通冻结相机渲染、参考标注/可解释测量、差异可视化、修复及复测。普通视觉失败由执行代理继续处理；声明“无人值守优化器”另需实际运行过自动修复适配器。
- 同一几何版本、相机、原图和测量脚本记录哈希。相机/ROI/测量定义变更时同时重测旧基线与新候选，保留变更原因；不追改旧报告。
- 锚点必须独立来自参考；把模型投影点回填为参考观测会产生虚假零误差，不能用于校准通过。拟合残差小也不等于完整相机姿态可辨识。
- 原生像素、渲染缩放和裁切/填边须可换算，记录采样分辨率和标注误差。显示成零的量注明分辨率限制，不宣称几何完全一致。
- 分区测量屋顶、前后过渡、机盖及车身端点，不能用中央屋顶平均值代表整条上轮廓。阴影、窗内孔洞和底盘未分割时不计算整车轮廓通过率。
- 未校准视角、缺失内部特征指标必须阻止整车通过。局部误差改善只报告局部结论；功能测试、构图测试、变形 Jacobian 检查独立列出。
- 修复被几何安全检查拦截时保留失败记录、扩大受控变形范围或更换表达；禁止降低安全门槛换取导出。

案例坐标、像素阈值、车型专用修形代码只存案例目录，不复制为通用默认值。

## 必交叠图证据（不能仅做并排看图）

每轮造型修订必须保留参考原图、同机位模型渲染、可调透明度叠图和轮廓差异诊断；至少覆盖本轮受影响的正交主视角及一个斜视角，并回归其余已冻结机位。执行顺序为：独立参考锚点标注 → 机位/尺度/位置校准 → 冻结参数 → 修改前后使用相同参数重渲染 → 对照关键结构 → 决定继续修复或通过。不能用二维非刚性拉伸把模型截图“贴合”原图。

每份证据记录原图和模型哈希、渲染尺寸、投影、相机、裁切/缩放/平移参数、标注误差及未解决透视差异。用于校准的点不得同时当作独立验收点；未标定视角仅可诊断，不能宣称像素匹配或整车通过。没有可靠参考分割时，显示模型轮廓和参考人工标注，不能伪造参考轮廓或 IoU。

叠图文件及清单是首版造型检查的必要输入。漏项、错误朝向、无法解释的轮廓偏差仍进入校准或修复，不以程序可运行、功能通过或肉眼比上一轮更好结束授权工作。通用规则留在本文件，车型锚点、校准参数及图像留在案例目录。

差异图默认使用高对比双色：模型轮廓超出参考为红色，参考有而模型缺少为蓝色，重合部分淡化，标注/分割误差带弱化。半透明叠图仅作辅助，不作为唯一差异图。先分离车体与背景/地面阴影，对透明玻璃、孔洞和轮胎遮挡说明统一处理；展示分割掩码供审计。外轮廓差异与窗线/灯具等内部特征误差分别记录，不能把材质反光或玻璃透明误判为几何缺损。


实际执行须同时遵循 [首版执行门禁](execution-gate.md)，绑定当前运行资产和逐视角证据；不得仅凭手填结果或旧截图声称通过。
