# 展示交付与案例接入

适用于新建与修复、车辆与非车辆对象。最终交付区分模型资产、单模型展示包、项目统一案例页三层。统一案例页是项目指定的消费端，不是所有任务必须创建的入口。

## 交付目标

在任务开始或恢复时读取项目已有交付约定，记录所需资产格式、单模型页面用途，以及是否接入统一案例页。已有明确指定的页面与布局直接复用；目标不明确且影响交付时再询问。不将本机案例地址、车型或选配数量固化为通用要求。

- 模型资产：同一版本的Spec、Three.js模型、必要资源及目标格式资产，沿用现有验收和导出规则。
- 单模型页面：通用对象使用适合交付用途的展示页；车辆复用已确认配置器。开发校对页可作内部证据，不能未经审查直接当成用户要求的最终产品界面。
- 统一案例页：项目明确要求时必须完成接入。保留已有案例切换方式、左侧模型及操作、右侧选配，以及移动端布局；无授权不重做页面框架。对象不具备的部件或动作不伪造，也不强加车辆选项。

## 打开和展示页面时的目标判定

用户要求“打开页面”“看看模型”时，先从当前请求与前文已确认的交付目标确定页面用途。明确链接或明确要求查看当前页面时使用该目标；否则，前文的统一模型展示要求优先于环境自动附带的当前浏览器地址。环境地址只是线索，不是用户选择。上下文已明确时不重复询问；存在多个实质不同的目标且无法判断时才澄清。

- 统一模型/全部案例：打开项目统一案例入口，保留或选择有效案例；不能改用升级进度、测试报告或单模型审查页。
- 单模型：使用指定版本的展示页；用户要看试验候选时才打开对应候选页，并说明版本性质。
- 审查/进度/对照：打开对应证据页面，不将其称为最终模型页。

打开前核对页面标题与结构是否符合用途；HTTP 200只说明资源可访问。统一模型页还须实际加载模型，核对案例选择器、目标案例和模型画布/加载状态，不能只验证外层HTML或iframe存在。页面打不开时启动正确目录的本地服务并复查，不因其他页面可访问而替换目标。记录已验证的地址、用途与结果；工具仅返回queued时，只能报告已请求打开，不宣称已在用户窗口显示。

项目交付记录应明确统一入口、案例目录、单模型地址来源及审查页用途；项目地址保存在项目内，不写死在通用skill中。

## 接入步骤

1. 找到项目实际案例目录、模型加载接口和共用控件，按下文“版本核实与成果继承”核对当前实际展示及本轮施工来源。复用现有注册格式，不另建重复入口。
2. 先完成模型、资产及单模型页面的必要验收和导出，保留不可覆盖的交付包。隔离候选、失败结果和诊断包不能注册为正式展示版本。
3. 在项目授权范围内登记稳定案例ID、显示名称、交付版本及可加载地址；通过项目记录关联对应Spec/包摘要与验收证据。按已有接口绑定实际颜色、部件变体、场景、视角和动作。
4. 替换已有版本时保留旧地址和版本记录以便回退；不修改其他案例的模型。统一菜单、布局和功能以项目已确认约定为准，不顺手增加调试或中间态入口。
5. 在统一案例页实际加载并检查后才报告接入完成。页面集成产生几何、资源或模型逻辑变化时，相关旧验收失效，须重建并复验。

没有指定统一案例页时，交付独立资产和页面即可；若任务仅要求资产，不强制追加网页。指定接入但目标页面或加载接口缺失时，明确缺口并请求必要决策，不擅自创建替代产品。

## 接入验收清单

- 目标案例加载的模型和资源对应已验收版本，无缺失资源、脚本异常或重复界面。
- 下拉或其他既定案例切换直接可用；切换再返回加载正确案例，不串色、不串部件或动作状态。
- 左右布局、菜单顺序、命名、角度和场景遵守项目约定；桌面和移动端均可操作，无溢出或遮挡。
- 所有声明支持的选配和操作作用于实际模型；动作关闭或复位后恢复正确状态。未支持的能力按项目约定隐藏或说明。
- 原版本可恢复，其他案例的导航与关键操作通过回归检查。
- 记录实际检查的页面地址、案例ID、交付版本、证据和未解决项。模型验收与页面接入分别给结论，不互相代替。

## 当前实现边界

`project.py build/export`负责单项目模型页面、资产与证据打包，尚不提供通用案例自动注册命令。案例接入须按实际项目接口实施并单独验证；本规范不宣称脚本已经自动执行上述检查。接入本地页面不等于部署、推送或外部发布，后者仍按用户授权单独处理。

## 版本核实与成果继承

适用于恢复已有案例的修改和替换展示版本。沿用 project/state、现有任务报告和采用质量阀，不新建审批阶段；仅盘点时不改注册或模型。

- **当前展示**：从用户明确对象和项目目录确定 case ID、来源版本、页面及模型入口；浏览器环境地址只作线索。实际加载后记录资源身份、ready、截图和脚本错误。核对运行时真正消费的模型数据，不能只看入口 JS、文件夹日期或 URL 上的版本文字。
- **施工基线**：分别列明当前生产版、已接受但未接入的样件、本轮候选。用户认可方向不等于正式认证，也不代表样件已接入。选择生产版或已接受样件作为基线并说明理由；多个来源需先生成可重建的明确合成版本，不能把相互依赖的网格直接拼起来。
- **成果处理**：复用任务记录列出相关已接受成果，每项标为 inherited / deferred / superseded，并说明原因。继承项在最终候选上复验，不能因基线含该成果就假定后续仍保留。延期项明确向用户报告，不隐瞒遗漏；新方案替代旧成果时说明依据。无相关样件允许空清单，简单修复不强迫合并历史试验。
- **实际接入**：采用审查继续按原规则执行。接入后打开用户的统一案例，检查目标来源、实际模型资源、换色保护、已有动作及复位；切到其他案例再返回，核对版本和状态。保存注册前后快照及恢复位置。模型未接入时明确说“样件完成，案例未更新”。

### 可重复记录检查

`scripts/version_handoff.py`提供 resume 和 delivery 两次记录核对，不自动启动浏览器、修改模型或写注册。代理通过已有浏览器/捕获工具采集证据，再从现有报告整理下面的轻量记录。无需手工维护另一套 Spec 或复制所有任务状态。

```sh
python3 scripts/version_handoff.py HANDOFF.json --phase resume --out NEW_RESUME_RESULT.json
python3 scripts/version_handoff.py HANDOFF.json --phase delivery --out NEW_DELIVERY_RESULT.json
```

全部文件引用为 `{path,sha256}`，路径相对 HANDOFF；所引用 JSON 内的文件引用同样相对 HANDOFF。只有 adoption_review 内部路径沿用其原有规则，相对审查文件本身。`--out`要求新文件，工具不会覆盖证据。

记录字段：

| 字段 | 内容 |
|---|---|
| version | 1 |
| production | target、asset、registry、observation；registry 是施工前注册快照 |
| baseline / baseline_reason | 实际施工基线文件引用与选择原因；须来自生产版或已登记接受样件 |
| inventory | 相关接受成果清单的文件引用；JSON 含 accepted_work 数组，每项 id、asset、acceptance 文件引用 |
| inheritance | 与清单逐项对应的 id、status、reason；delivery 的 inherited 项另有 evidence 文件引用 |
| candidate | delivery 要求的最终实际模型数据文件引用 |
| adoption_review | delivery 复用现有采用审查原始文件，重新运行 adoption_check；不只相信旧 result 中的 adopt 字样 |
| installed | delivery 的 target、registry、observation 和 rollback 恢复位置 |
| required_operations | delivery 的本轮及保护范围操作 ID 数组；已有换色/动作等按真实能力填写，不伪造不存在的操作 |

`target`包含 case_id、source、page_url、model_url；URL 使用实际完整地址，source 是项目现有来源标识，不硬编码为某供应商。页面允许带不同版本参数，但同一次 observation 必须与该 target 精确对应。

`observation`引用真实浏览器采集 JSON，字段为 target、asset_sha256、registry_sha256、ready、errors、screenshot 文件引用；delivery 另有 checks:{操作ID:true/false}。asset_sha256 从真正模型数据响应计算，与 asset 采用相同字节层级（例如均为 gzip 运输字节，或均为解压数据），不得直接抄入预期哈希。registry_sha256 对应该次注册快照。必查 switch_return、reset，其他操作复用现有测试报告。截图文件被哈希绑定，但工具不看懂截图。

继承 evidence 的 JSON 包含 work_id、candidate_sha256、passed，指向对应成果在最终候选上的实际检查结论；具体几何/材质/动作比较证据继续保存在原任务报告，不把这个布尔值当成自动形状检测器。

模型数据之外的材质、贴图、运行代码等仍按现有 bundle 清单、采用审查和功能检查验证。本工具的单个 asset 身份不证明整个资源集合相同，也不能替代它们。记录不完整、版本错配或证据过期时先纠正记录/接入，不因脚本失败自动回退或覆盖模型。

### 实现边界

该工具检查已提交记录的哈希、成果覆盖、候选绑定、采用决定和操作结论一致性；不自动发现遗漏的历史样件、不理解接受记录的语义、不执行页面交互，也不证明视觉质量。`project.py next/build/export`不会自动调用本工具；指定案例的恢复和接入由执行代理按本文调用，不宣称所有宿主已具备自动发布保护。适用于使用同一技能的宿主，不依赖 ChatGPT 专有 API。

### 替换已有默认版本前

已有已接受模型时，先完成 [采用质量阀](adoption-review.md)，运行 `adoption_check.py` 并读取结果；只有 adopt 才更新默认案例注册项。retain-baseline / pending / invalid 保留原注册项，单独标记候选。恢复版本后检查实际 iframe/资源身份和受影响交互；审查页也要标明撤回状态，避免历史技术通过被误读为采用通过。此脚本是采用前检查，不自动接管 export 或注册写入。


## 轻量展示交付

接入 [轻量展示交付 v1](lightweight-delivery.md)：新建构建默认采用独立或锁定模板兼容的无损压缩数据，界面不重复加载完整几何。分别记录展示资产预算、解压规模及设备性能；现有功能、视觉、交换验证和采用质量阀保持有效，打包通过不代替这些结论。

## 共享运行时与局部回退

模型身份之外，按 [运行时依赖校验](runtime-guards.md#预览发布和回退) 绑定实际消费的共享JS/CSS/贴图与资源清单。只替换模型、共用可变主站脚本的预览须标明“共享运行时”，不能称完整冻结版；冻结历史预览应保存完整依赖身份。

回退仅合并目标case/source条目，保留其他案例后来已认可的更新；整份旧共享注册表不能直接覆盖当前表。目标条目已被后续修改时停止覆盖。共享脚本无法独立回退时，先明确影响范围并在隔离副本验证。通用工具只处理结构化注册投影，不猜测项目JS写法，也不自动执行回退。

发布前把Git已跟踪改动、未跟踪新模块、静态/动态导入、import map和浏览器实际请求合并成声明依赖清单，核对每项在发布包内且摘要一致。静态扫描无缺失不能代替动态加载和已有跨案例回归；发布授权沿用用户规则，不因校验通过自动推送。
