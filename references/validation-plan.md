# 分层测试和放行

| 层级 | 执行内容 | 能证明 | 不能证明 |
|---|---|---|---|
| 软件 | unittest；错误输入与失败注入 | 阶段、哈希、边界和数据检查行为 | 图像还原优秀 |
| 构建集成 | Spec→mesh→Three factory→实际导入/场景树 | 模块能连接和被Three消费 | WebGL截图与外观正确 |
| 开发回归 | 已知车参考固定机位；闭合/开启/内外观察 | 已有问题是否重现 | 新对象泛化 |
| 独立重建 | 新车及非车辆；冻结输入、限时、固定环境 | 首版质量、返工、速度与失败率 | 任意对象/工程尺寸精度 |
| 交付运行 | 实际配置器操作、资源、恢复、加载、目标设备 | 被测功能与设备表现 | 未测设备性能 |

独立比较使用同一输入、同一模型/工具环境、同一时间预算和同等上下文。旧流程与新流程各至少三个独立运行，分别记录首次可运行时间、首次达到预定质量时间、人工介入、总时长、工具成本、返工次数与失败数。未达标按失败计入，不能只取成功最快值；小样本报告单次结果和范围，不夸大统计结论。

质量合同在执行前确定，按实际用途设轮廓、关键点/线、局部曲面和装配门槛；以标注不确定度解释像素值。渲染必须同相机、同画幅，并检查关键特征，不能只靠轮廓IoU。失败定位后若重用样本开发，则移入开发集，另选最终盲测输入。

凡已用于选择方法、调整参数或修复问题的样本都属于开发集。新的独立试验需另行冻结未见输入和标准；单次结果只证明该次观察，不能替代重复测试或宣称一般速度优势。具体案例状态保存在任务报告，不写成永久规范。


v0.3开发回归增加 car-wheel / bicycle / motorcycle / toy 四个明确设计的样例。测试必须覆盖无关零件不变、变体保留轮胎、动作中间态及复位、隐藏零件不被点选、UV/贴图身份、导出默认变体，以及真实Blender导入。功能样例不构成任何照片还原评分。详细分层清单见 asset-acceptance.md。

局部几何改造增加同相机旧/新灰模、参考ROI与侧/斜视复查。检查体积关系实际改变、边界连续、相邻部件不退化，并在语义拆分后重跑选件/换色/拆解复位。软件阶段门禁可通过缺局部check、数值冒充视觉、陈旧几何哈希等失败注入验证；这类测试不证明局部造型正确。
