# 图片与模型共用的集中优化流程

目标：复用当前任务已有的有效资产和通用修形经验，用一次完整诊断及有顺序的优化计划减少试错，使可观察造型尽可能接近参考实车。一次集中优化包含必要的多个检查点；不承诺任意输入一次执行即可恢复真实隐藏结构或达到高保真。

按 [稳定执行与验收门槛](optimization-gates.md) 先确定范围和检查点。完成标准包括关键特征覆盖、独立验收及无不可接受回归；不是操作结束、平均误差下降或网页通过。

## 1. 选择起点，保留已做对的部分

| 输入情况 | 起点与复用 | 应补的步骤 |
|---|---|---|
| 用户模型，比例基本合理 | 保留原件、材质、贴图与 UV，以其副本为基线 | 只做有证据的问题区域；不默认重新造车 |
| 用户模型，已有更好的同车版本 | 对照参考，选择造型更合理的版本；检查车型/配置、朝向和尺度一致性 | 保留已通过部件，补当前差距；最新版本不自动等于最佳版本 |
| 图片，任务已有同车基础资产或候选 | 对照原图选择可复用候选，来源标明复用模型 | 补参考/基线检查与必要修形，不重新生成全部图片/模型，不把导入模型说成从图生成 |
| 图片，没有可用基础资产 | 先建立比例和轮廓候选，使用已授权且可用的生成服务或有相应能力的本地建模工具 | 基础造型通过后进入本流程的分区优化；粗估截面只算候选 |
| 模型，无车型参考图或尺寸 | 保留模型可见设计，检查表面/结构/材质问题 | 可做资产质量优化，不能声称已证实更像真车；新增参考后再校准形似 |

候选选择依据是原图同视角的轮廓、比例、窗线和主要特征，不按面数、反光漂亮程度、文件大小或版本号排序。不可把外观不同的车型强当模板；同车不同套件也需登记差异。

先读任务已有 project、评审、参考包和资产清单，复用有效模型、相机、轮廓及部件。首次任务不要求完整历史，也不要求用户事先提供官方尺寸。原件独立保存；只有必须替换的局部才重建。

## 2. 一次集中诊断，固定目标和证据

已有 GLB 先用 asset_manifest.py 和实际 Three.js 页面检查；需要 Blender 诊断或编辑时再用 inspect_model.py。图片按 image-pipeline.md 整理来源和 ROI；已完成且身份一致的检查可以复用。以灰模与原材质两组实际视图检查前、侧、后和主参考角，缺少真实视角时标明推断。

建立当前任务的坐标、尺度依据和参考相机。透视/裁切/配置不一致先处理；相机不对齐时不下像素造型结论。fit_camera.py 的拟合点与独立复核点应覆盖所评目标，不只凭轮胎或少量容易匹配的点认证整个车体。

问题按下表排序。每项写参考证据、模型证据、原因假设、范围和目标，不能只写“更平滑”“更精细”。

| 优先级 | 判断对象 | 处理顺序与进入条件 |
|---|---|---|
| A：判断条件 | 车型/套件、轴向/尺度、参考矛盾、相机 | 先保证对照可解释；不通过时记录未知，不随意改几何迎合矛盾图片 |
| B：整体造型 | 车长高宽关系、轴距、前后悬、屋顶/A-D柱走向、窗线、轮拱与前后外轮廓 | 先改这些可识别车型的骨架；整体明显不符时不得消耗修形预算做玻璃痕迹、车漆或轮辐美化 |
| C：分区结构 | 机盖/翼子板/门板/车顶体积，窗框/玻璃接合，灯腔与主要饰件位置 | B 已通过或问题仅在局部时处理；每个区域有共享边界和邻接保护 |
| D：表面与细节 | 皱褶、接缝过渡、法线、倒角、把手、灯具和轮毂细节 | 不破坏 B/C 已通过成果；几何轮廓错误不能仅修法线 |
| E：材质与交付 | 材质归属、UV/贴图、展示灯光、网页体积与交互 | 相关几何可用后校准；原材质准确的部分保留，功能检查不能替代形似验收 |

已通过或没有问题的层级直接跳过。少量针对性的临时显示修复可用于看清 B/C，但需明确诊断用途，不能记作整体造型改善。

## 3. 先写一份集中优化任务卡

复制 [optimization-plan-template.md](optimization-plan-template.md) 到任务 repair-plan.md。确定基线、目标、允许变化、保护特征、动作依赖与验证，再开始局部执行；已授权本地优化可自主推进，不逐项重新要求确认。

固定原输入→基线→结果三份身份及可比视图，记录收益分别来自基线选择和加工。对形似验收冻结结构化计划；声明关键特征组、独立点、机位/标注不确定性、允许回归和退出标准。参与反馈调参的点不能继续标为独立。参考不支持整车时限定可观察范围，保留完整范围未通过。

一份计划应覆盖本轮主要问题，避免“看到一个小毛病就改一次”。先选最影响形似的关键区域验证方法；正确后沿同一方法处理同类区域。样板用于判断方法，不能成为避开整体比例问题的理由。

保护分三种：保持局部几何/UV/材料不变、随所属部件协调移动、明确允许重建。比例改变时把手等可能需要跟随门板移动，不能既锁死世界位置又改变载体。保护规则、坐标空间和允许变换写在任务中；单一融合网格还需检查非允许区域顶点/面，不能只比较对象名称。

局部改位前执行 [特征保护](feature-protection.md)：冻结真实边界/角色域与安装关系。独立构件应优先在不改变可信载体的条件下重新安装；载体必须修改时先固定门缝、窗线和折线，保护交叠或间距不足时转为分区重建，不仅扩大过渡带。

位移上限、拟合邻域、采样尺度、曲线圆角、缝隙和误差目标都根据当前资产尺寸及证据精度确定，不从某辆旧车复制固定坐标或毫米阈值。没有可信尺寸时使用估算尺度和相对比例，保持来源说明。

## 4. 按问题选方法，按依赖执行

从 [shape-optimization-methods.md](shape-optimization-methods.md) 选择方法，并按 [tool-routing.md](tool-routing.md) 选择执行工具和持久化方式。已有 GLB 优先 Three.js／原生属性加工；复杂建模再进入 Blender。通用经验是方法的适用条件、输入、保护和校验；任务实例才包含具体轮廓、区域、节点与数值。

- B 明显不符：先调整基准位置/主要曲线和控制截面，或更换可信度更高的基础候选；全局光顺不会恢复正确车型。保留正确部件，只重建错误范围。
- C/D 的局部表面问题：优先保留已有拓扑与 UV，以空间均衡、受限曲面拟合处理；邻域不得跨越真实折线、内外壳和保护特征。
- 相邻玻璃/框/密封边：共用轮廓及载体表面；同步处理被替换的旧面。不能各自拟合、单独贴平面后再靠偏移隐藏穿插。
- 大面加工前登记小构件；拟合样本排除把手/镜座/灯腔等真实凸凹特征。需要恢复时使用可信原件位置/形状，不平滑到消失后重新臆造。

所有路线保存脚本/参数/输入输出哈希、阶段依赖及评审；Blender 路线使用 blender_pipeline.py，Three.js／原生 GLB 路线在任务目录保存等效记录。浏览器内存修改须按任务选择写回派生 GLB 或交付可复现的运行时适配，重新加载实际交付版本验收。有材质的模型始终保留原材质副本；灰模仅用于诊断。现有辅助脚本只覆盖其真实实现，曲面优化仍需代理编写/适配当前资产脚本，不能把方法文档当自动算法执行。

原生属性加工须审查允许域与特征约束；可保持原 GLB 的 UV/材料/索引时优先保留。Blender 导入副本仅在确有母版/诊断需要时生成，不默认用其重导出覆盖无损 GLB。参数从当前尺度/支持域推导；代表区域和相关视角试修有可辨改善、无关键回归后再扩大。

在任务卡中按输入质量、目标差距、成本和可辨改善空间明确设置 `max_repair_rounds`，它只限制同一连续修复链的反馈次数，不是整个集中计划只能做几项操作。比例→分区→材质可以依赖通过后分别推进；同一未通过目标不能改名、去依赖或新建目录重置预算。连续两轮没有实质改善时重新诊断基础资产/参考/方法，保留最佳版本，说明需要的方法改变或新增条件；不继续盲修。任务预算已冻结后不能为通过而静默加大。

## 5. 对照验证与回退

每个主要检查点采用相同机位、灯光及材质做改前/改后对照，再看当前参考角和其他可用视角。参考相机已对齐时记录独立关键点或定义清楚的轮廓误差、单位与不确定性；没有可靠测量时给具体视觉差异，不造相似度百分比。

| 验证层 | 必须能回答的问题 |
|---|---|
| 整体造型 | 车身比例、屋顶/窗线、轴位与前后轮廓是否接近参考；多个视角是否同时合理？ |
| 局部修形 | 原问题是否改善；邻接区是否出现拉伸、漏面、穿插、尖刺或反光断层？ |
| 成果保护 | 已通过部件/特征、UV、材料和贴图是否按允许范围保持；局部坐标与世界变换是否符合计划？ |
| 导出与运行 | 派生 GLB 的索引/角色是否仍正确，原材质依赖是否完整，实际网页是否复现并支持已启用功能？ |

出现退步时撤回该步，继续使用更好的基线；不因局部更光亮或网格更细就提升为正式模型。B 未通过时 C/D 局部通过不提升整车 verdict。几何、材料、功能和目标设备性能分别记录；诊断预览不等于正式验收。

按冻结计划逐项检查关键目标，任何关键失败不得用平均值掩盖。用 optimization_review.py 核对哈希、点误差、独立性、视角覆盖与保护记录；consistent 只说明记录逻辑一致，仍需实际视觉评审。已达到本轮范围即停止；改善低于输入噪声时重新诊断，不追虚假精度。

## 6. 复用记录，下一次只做差量

任务保存基线选择、参考/相机、问题清单、已通过区域、实际方法参数、保护与评审、剩余差距，以及完整版本身份。下一次先读取它们，继承已通过成果和已验证方法，不重走全部探索。

复用检查结果须核对模型哈希、参考/配置、坐标与绑定身份。模型换了，只重查受影响几何/相机/角色；参考改变时复核相机和目标，不自动丢弃正确贴图/构件；导出重排索引时重新绑定。旧脚本的硬编码不能直接套在新车上，复用算法并适配任务输入。历史失败方法同样记录，避免再次扩展未经验证的粗坯。

交付说明哪些形似目标通过、哪些只能推断、哪些仍待修订，及最优可回退版本。方法沉淀到 Skill；车型坐标、素材、阈值与一次性日志留在任务，不写入长期 memory。


宽缝、轮胎旁浮线及接缝断续按 [接缝诊断](seam-diagnostics.md) 区分载体、间距和描边问题。完整首版按 [首版清单](first-version-checklist.md) 组织内部连续验收。
